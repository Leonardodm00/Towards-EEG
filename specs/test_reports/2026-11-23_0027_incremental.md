## Problems in the spec
- S1. `soma_fit.crop_margin_um` (default 1.0 um) and `soma_fit.figure_planes_um` (default (-8, -3, 0, 3, 8) um) appear only in section 6's row: no Parameters list names them, states their defaults or their refusals. The refusals of amendment 1's start settings are not stated either; the code refuses start_core_radii >= start_far_radii, a clip outside (0, 1), start_ratio_none outside (0, 1), a percentile outside [0, 100], a negative margin and an empty or non-finite plane list. The tester's refusal tests assumed only what the mathematics needs (varrho in (0, 1) for mu_0 >= 0, finite values).
- S2. Blocks 46 and 47's Data-flow lines say the fit consumes Block 44's files (`soma_<S>_block.npz`; `soma_<S>.json`'s centre, radius, dz and `transform`), while section 6's `fit_soma.py` recomputes the traced soma from the SWC with its own ALIGN arguments and fetches its own crop (region + `crop_margin_um`), reading none of Block 44's outputs. The two agree only when Cells 24 and 25 are given the same alignment; nothing checks it.
- S3. Section 6 does not say whether `fit_soma.py` refuses a `--soma-k` outside the window or not recorded, as `show_soma.py` does (Block 44 amendment 1 (v)). The code accepts any integer; with `--synthetic` every plane is valid, so the case could not be run here; on real data a window without enough valid planes reaches `select_planes`' ValueError (a traceback rather than an argparse error).
- S4. Block 47's T3 ("every other node unchanged bit for bit", the fitted ellipsoid larger than the traced sphere) holds only when no stem is walked: under D-222.5 a stem whose P2 lies inside the larger fitted surface loses nodes. The tester's T3 places every P2 outside both test ellipsoids; T4 covers the walk.
- S5. D-013's byte identity ("only radii change") holds for radius-only writes; the corrected-soma SWC rewrites x, y, z and radius on every kept line with the token's decimals, at least 4 (Block 47 says so), so a line is byte-identical only when its tokens already carry at least 4 decimals in fixed notation. True of the synthetic file's dendrite lines; not checked on a real Allen file here.
- S6. Blocks 44 and 48 have no "Confirmed" line (who decided their numbers and choices); Block 44 says its numbers are the orchestrator's, PROVISIONAL.
