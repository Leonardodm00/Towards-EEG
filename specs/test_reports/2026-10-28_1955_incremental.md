## Oracles derived from the spec
These were recorded from SPEC.md before any source file was opened (step 1). Nothing in scope is marked `Confirmed: inferred`.

Block 10.S (the stripe), D-101.2-4:
- O1 shadow depth: `D(rho) = B int_{-r}^{r} (1 - exp(-2 mu sqrt(r^2 - v'^2))) phi_sigma(rho - v') dv'`, against `scipy.integrate.quad`. The tolerance is 2e-3 of the dip at rho = 0 (the spec allows the Gauss-Legendre rule a ripple "at the 1e-3 level"). Limits: as sigma goes to 0, `B(1 - exp(-2 mu sqrt(r^2 - rho^2)))` plus its second-order blur term; as mu goes to infinity, `B(Phi((r - rho)/s) - Phi((-r - rho)/s))`.
- O2 tau margin `rho_tau`: the root of D(rho) = tau, against `scipy.optimize.brentq` on the quad-based D. It is -1.0 exactly when D(0) <= tau. It increases with B, mu and r, and decreases with tau.
- O3 masks: neighbour q shades a pixel when its 2-D distance to the segment is <= rho_tau(max end radius, sigma_r(max over ends of |z_end - z_k|)). The own branch (both end ids in `branch.ids`) shades the same way with radius max(d_hat/2, r_Allen), or Allen's radius when d_hat is not finite. A soma disc shades as a tube of radius r_s at the stage's largest blur. Without a finite positive B_bar and mu, every margin falls back to the geometric `r + n_sigma sigma_r` of 10.P.
- O4 stripe: the band |u| <= W is cut into one-pixel columns along v. The walk passes the own-shaded columns (v_own) and stops at the first column shaded by anyone, or at the patch's end (L). Then side = L - v_own, and N(W) = the clear band pixels of the run columns. W* = argmax N, the smaller W on a tie. ok holds iff N >= 500 and both sides >= 3 um and b0 > 0; otherwise `bg_few`.
- O5 known answer (a): a parallel neighbour at D on +v gives L+ = D - rho_tau(nb), v_own = rho_tau(own) and L- = the patch edge (each within one pixel), with W* the widest. Rotating the scene keeps N within 3 %.
- O6 invariants (c): the stripe lies in band(W*), holds no shaded pixel, n_pixels = |mask|, N(W*) >= N(W). Mirroring swaps the sides. A neighbour within 3 um on both sides gives `side_short`. With no segment, the stripe is the band to the patch edges minus the own cylinder.
- O7 `square` equals 10.P's far mask bit for bit, has no stripe record, and restores 10.I's verdict (`not_isolated` exactly when a neighbour's predicted depth in the patch exceeds 0.03 gl).
- O8 the verdict before the fetch is "the same test at the plane nearest the pilot's depth", on `patch_frame`. `patch_frame` addresses the same pixels as `fetch_patch`.
- O9 contract: info keys, bool masks, the reason names `not_isolated:too_few|side_short`, `PlaneScan.stripe` through the scans JSON (strict JSON), and an old file without it loads. The new `CalibrationConfig` fields are in no signature: the default hashes stay estimator 59678d4e2aedf2b6 and simulation 52aa73e479eb77cf. `validate()` refuses illegal values. Determinism.

D-101.1 (flatness per set):

Neither set is judged by the near bound, after `allen_diameter_out`/`_missing`. A NaN phi is not flat. The tail of `calibration_reasons` and `candidates_from_rows` follow the same rule.

## Problems in the spec
- S1: Section 6's Phase I sequence names the patches `patches_near.npz patches_far.npz`. `synthetic --out S_near.json` writes `S_near_patches.npz` (`patches_name` replaces "scans" in the basename, otherwise it appends "_patches"). Run as written, `figures` exits with `FileNotFoundError: 'patches_near.npz'` (verified).
- S2: 10.S says that without a finite positive B_bar_j and mu_hat_j the margins fall back to 10.P's geometric rule. It does not say whether the pre-fetch verdict then runs. The code skips the isolation test in that case (`trace_reasons`), while the scan uses the geometric stripe.
- S3: `not_isolated:too_few` and `:side_short` are given as alternatives with no precedence. The code reports `too_few` when both hold.
- S4: `stripe_min_side_um` = 3 um is justified as "the profile's half-length". That is 3 um for the near line but 10 um for the far line (`far_profile_half_um`), and the spec applies 3 um to both sets.
- S5: Block 10's "Custom code" and "Library calls relied on" lines predate 10.S: the tau-margin search, the shadow masks and the stripe walk are not listed. The 10.S API omits `shadow_masks(..., sigma_soma_um=None)`, which is the code's only way to pass the stage's soma blur (relevant to F1).
- S6: Oracle (a)'s "the same scene rotated by theta gives N within 3 %" holds only when no run ends at the square patch's edge: the square clips a rotated band differently.
