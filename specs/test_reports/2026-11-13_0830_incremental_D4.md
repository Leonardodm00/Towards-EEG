## Problems in the spec

- S1: 15.2 "v_c within half the window of its start" is ambiguous. The code bounds v_c to +-W/2, with W the
  window's half-width (`far_field.py:84`); "half the window" could also mean +-W.
- S2: Section 6 lists only `test_smoke_calibration.py` for Block 10 and no command for Block 15's own oracle suite
  `test_smoke_far_field.py`. Nor does it list `test_smoke_calibration_scene.py`, `_figures`, `_stripe`,
  `_candidate_search` and `_isolation_view`, which the entries of Blocks 10 and 15 name. This run took them from the
  block entries.
- S3: 19.5 writes "(omega - c + sigma_r(0)^2)^(1/2)" without saying whose sigma_r(0): the configured one, or the one
  the calibration's table was built with (F2).
- S4: Block 10's knot count is stated with P = `offsets_planes`, and the code reads it from the data (F1). The rule
  "a knot with no observation in either adjacent interval is NaN" does not say which interval holds an observation
  lying exactly on a knot. With the axes exactly on the planes, the 1.12 um knot counts as observed through the
  observations at 0.84 um, although its value is identified by nothing. The fit then reports the solver's start
  value (0.0 um^2 in the boundary test's printout).
- S5: 19.1's "in the SWC's order" differs from the stretch order the code uses (F5).
- S6: 15.3 says that nodes without A_j or with too few planes are "dropped and named", but gives no names. The code
  uses `no_area` and `few_planes` (`far_field.py:265,275`).
- S7: Block 10's 10.P oracle "to 0.01 gl with 2 gl of noise and 1 % of debris pixels" is below the plane estimate's
  own standard error (2 gl / sqrt(about 4000) = 0.03 gl), so it cannot hold for an arbitrary noise draw. It needs
  its design (pixel count, seed) or a tolerance in standard errors. This run used 5 standard errors.
- S8: The Public API lines are out of date (F8). Public implementations with no spec entry:
  - `calibration.gaussian_core_fit`, `line_geometry`, `stage_planes`, `patch_images`, `trace_reasons`,
    `PILOT_RECORD_FIELDS` and `pick_se` (named only in 19.6's status);
  - `calibration_scene.patch_bounds`, `pixel_centres`, `segment_margins`;
  - `far_field.far_offsets`, `FarSelection.subset`;
  - `calibration_report.growth_curve`, `stage_inputs`, `gaussian_inputs`, `example_inputs`;
  - `calibration_io.kernel_to_dict`, `load_calibration`;
  - `calibrate_kernel.candidate_sources`, `weighting_record`, `weighting_words`.

  `far_field.se_model` also floors the core SD at 0.05 um and its window at 3 samples per side (`far_field.py:302,
  304`), which 15.4 does not state. Both guards are inert inside `fit_far_slope`, whose predicted SD is at least
  0.1 um and at least sigma_0 on the far planes.
