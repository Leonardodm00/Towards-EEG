### K. Blur kernels (D-046; `model/blur_kernels.py`)
- K1 Unit integral: for every family (gauss, lorentz, voigt, student, gennorm,
  skewnorm) and shapes on a grid including the bounds, `kernel_pdf(F, w, s)`
  integrates to 1 over R (`scipy.integrate.quad`, tolerance set by quad's own
  error estimate).
- K2 FWHM = w: the half-maximum points found by `brentq` on g(z) - g(0)/2, one on
  each side of 0, are w apart (relative 1e-9).
- K3 Mode at 0: g(0) >= g(z) on a fine grid; for the skew-normal the mode m_F(a)
  is the root of -z + a phi(az)/Phi(az).
- K4 Closed-form unit FWHMs: gauss 2 sqrt(2 ln 2), lorentz 2,
  student 2 sqrt(nu (2^(2/(nu+1)) - 1)), gennorm 2 (ln 2)^(1/beta); voigt and
  skewnorm numeric.
- K5 Against scipy, independently rescaled in the test: g is the scipy unit
  density (norm, cauchy, t(nu), gennorm(beta), skewnorm(a); voigt =
  `scipy.special.voigt_profile` with Lorentzian FWHM / Gaussian FWHM = r) rescaled
  to FWHM w with its mode moved to 0.
- K6 Symmetry: even for all families but skewnorm; skewnorm g_{-a}(z) = g_a(-z).
- K7 `gauss_fwhm(sigma)` = 2 sqrt(2 ln 2) sigma: 0.2331 um at sigma_fit = 0.099 um.
- K8 Refusals: FWHM not finite or <= 0, an unknown family, a shape outside its
  domain -> ValueError.

### M. `tube_model.model_profile_kernel` (D-046; shared with Block 12)
- M1 Equals Bbar [1 - integral over |u| <= d/2 of (1 - exp(-alpha sqrt(1 - (2u/d)^2)))
  g(v - v0 - u) du], computed in the test by `quad` in u (independent of the
  code's Gauss-Legendre rule in psi; the substitution u = (d/2) sin psi gives the
  spec's form): 1e-7 grey levels for smooth kernels, 0.5 gl for the cusped
  generalized normals (the spec's tolerances).
- M2 With the Gaussian of SD sigma_fit it equals Block 3's `model_profile`
  (1e-11 gl).
- M3 I_model <= Bbar exactly (non-negative integrand, positive weights); I_model
  -> Bbar far from the tube.
- M4 Linear in Bbar; shift-equivariant (v, v0) -> (v + c, v0 + c); mirror
  (v, v0) -> (-v, -v0) for even kernels.
- M5 Convergence as the number of quadrature nodes grows.
- M6 float64 output of v's shape.

## Problems in the spec
- S1. Section 6 has no row for `tests/smoke/test_smoke_plane_iteration.py`, although Block 11's test oracles name
  it (D-042) and Block 13.1 lists it among Block 11's suites. Run here as Block 11's: 7 pass.
- S2. The pilot summary's "the share of converged nodes the dark flag removes": since D-030 (Block 14.1) and
  D-096 the dark flag removes no node from S. The code reports `dark_share_of_converged`, the share of converged
  nodes with alpha_hat > `alpha_dark_flag`.
- S3. `calibration_set` of a pilot row: the spec lists "near", "far" or "" but not whether a node that is not a
  calibration node carries its D_A set or "". The code writes "" (its docstring), and the summary's "rows without
  `calibration_set` counted under """ fits that reading.
- S4. Block 11's API line `survey.measure_nodes(swc, provider, cfg, transform, regs, only, log)` lacks
  `whole_stretches=True` (Block 17.2's; with False only the requested nodes are measured). This is an
  implementation without a Block 11 spec entry.
- S5. Block 11's data flow, "consumes Blocks 0, 4-8, 10": no Block 11 module calls Block 7 (`invert`, `fill`).
  The scripts import Block 8's `run_cell` only for `real_provider`. Block 11 does call Blocks 12 and 13, which the
  line omits.
- S6. Block 0 (a neighbour) is `Confirmed: inferred`. The verdict sentences Block 11's `registration_category`
  parses ("ON THE PROCESS ...", "ALONGSIDE: ...", "FAR: ...", "NOT ON A VISIBLE PROCESS ...") are described from
  Block 0's code. U9 and B8 agree with that description, which is no independent evidence that the sentences are
  right.
- S7. The IRLS cap means different things in two places. In Block 11 (D-046) it gives `irls_ok` False and the
  status stays converged or at_bound; a variant is `failed` only when a solve does not converge. In Block 12
  (D-053 (ii)) the cap makes the SGT fit `failed`. Both are implemented as written (F11 passes), and Cell 4m flags
  a variant by its status. The spec does not say whether the difference is intended.
- S8. `iterate_planes`' refusal list "(0, 2.5, True, "5", None, NaN)" does not say which values each of d0, m and
  R refuses. 2.5 is a valid d0 and m. The code accepts m = "5" and m = True through `float()`, and refuses None
  for d0 and m with TypeError, not the ValueError its docstring names (checked).
- S9. Block 8's per-node column list in the spec lacks `mu_d_hat`, which the code's `CSV_COLUMNS` holds since
  Block 14.5. Pilot rows do not carry it (it is not a NodeResult field), so "the NodeResult columns of the
  per-node CSV" in Block 11 means the first 25 columns, implicitly (F4).
- S10. Cell 4j's files list `planeiter_summary_<specimen>.csv` and `.png` without the condition stated for the
  evaluations ("With more than one node measured"); the code writes them only for more than one node.
- Mapping of spec to code (step 4): every Block 11 function the spec names exists with the spec's signature,
  except S4's extra parameter, and `iterate_planes(..., min_first_half_um=None)` and
  `gradient_iteration(..., min_first_samples=None)`, which Block 13.6 specifies. Implementations without a spec
  entry: S4's parameter and F6's "error: ..." status. No Block 11 spec item was found without an implementation.
